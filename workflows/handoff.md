# Handoff Workflow

Metadata:

- trigger: after meaningful multi-file work, debugging, architecture changes, or interrupted work
- inputs: goal, files touched, verification, blockers, decisions
- expected output: concise continuation note
- verification: handoff includes exact commands run or why they were skipped

## Steps

1. State the goal.
2. Summarize what changed.
3. List files or areas touched.
4. Record verification and results.
5. Name remaining risks.
6. Give the next useful action.

## Handoff

If the work should be durable, add or update a session log in `Session Logs/`.
